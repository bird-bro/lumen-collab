## Intent Lock

- **Change name**: sign-log-query
- **Problem to solve**:
The console has one log page (操作日志) while the 随访 permission-model reference ships two
(操作日志 + 登录日志); `log_sign` rows are written on every login/logout but no query
endpoint or page exposes them. Meanwhile the log tables are plain heaps where the OPS
reference database (rcp-test) uses `RANGE (date_ym)` partitioning for yearly detach/archive.

## Approved Behavior

From `specs/system-data/spec.md` (delta):

1. Log tables exist partitioned on a fresh database - **WHEN** a fresh database receives the
   migrations **THEN** `public.log_info`/`log_sign` are partitioned `RANGE (date_ym)` **AND**
   yearly partitions 2026/2027 plus one default partition per table exist.
2. Rows survive the conversion - **WHEN** the conversion runs on a DB with existing log rows
   **THEN** every previously visible row remains readable through the parent table.
3. Write into an unpartitioned year lands in the default partition - **WHEN** a sign or
   operation event writes a row whose `date_ym` year has no child **THEN** the row lands in
   that table's default partition instead of failing.
4. Query sign logs - **WHEN** an administrator holding `system:signlog:list` queries
   `/api/v1/system/logs/sign` **THEN** `log_sign` rows return newest-first with
   account/uid/dateYm filters applied **AND** no row carries a `token` field.
5. Sign-log permission is enforced server-side - **WHEN** a request without
   `system:signlog:list` reaches the endpoint **THEN** it is rejected even when the caller
   holds `system:log:list`.

From `specs/web-system-console/spec.md` (delta):

6. Filtered sign-log query - **WHEN** an administrator queries the sign-in log page with an
   account or month filter **THEN** matching rows return newest-first and paging works.
7. Read-only surface - **WHEN** the sign-in log page renders **THEN** it offers no mutation
   controls for log rows.
8. Menu-driven visibility follows the page permission - **WHEN** a user's permission set
   lacks `system:signlog:list` **THEN** the 登录日志 menu entry is not visible to that user.

## Design Constraints

- **Architecture/Decisions**: D1-D8 as recorded in design.md (copy-swap one tx per table;
  yearly partitions + `*_def` default; sequence ownership re-point; sign endpoint inside
  LogController with method-level gate; filters account/uid/dateYm; two pages not tabs;
  token never leaves the service; V13 DDL / V14 menu-seed separation).
- **Technical constraints**:
  - OPS-verified version train - no dependency version changes (JDK 11, Spring Boot 2.5.15).
  - Never modify existing public methods - additive overloads/methods only.
  - Never rewrite an applied Flyway migration - V13/V14 are new files; lumen-system keeps
    explicit `spring.flyway.schemas`/`default-schema` discipline.
  - Backend-first: the web page runs against the REAL backend via vite proxy; unit tests
    stub API client modules at the seam only; no mock data in pages.
  - English-only committed source; `@author birdbro` headers on new classes.
