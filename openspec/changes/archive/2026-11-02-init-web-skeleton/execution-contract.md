## Intent Lock

- **Change name**: init-web-skeleton
- **Problem to solve**: `lumen-web/` contains only role files - no `package.json`, no build,
  nothing to run. Create the Vite + React 18 + TypeScript + AntD 5 SPA shell: module layout,
  typed API envelope seam (empty), dev-server proxy to the gateway, token theming with red
  excluded, and one lazy-loaded department route pattern proving the shape later departments copy.
- **In scope**:
  - `lumen-web/package.json`, `pnpm-lock.yaml`, `tsconfig*.json`, `vite.config.ts`,
    `index.html`, `.gitignore` additions
  - `src/main.tsx`, `src/App.tsx`, shell layout, router with a lazy `radiology/` placeholder
  - `src/api/` seam with the typed `{ timestamp, code, msg, data }` envelope (OPS `R`
    contract) and a base-URL constant
  - AntD 5 `ConfigProvider` theme with design tokens; red excluded from primary palette
  - Dev-server proxy `/api/v1` -> the nginx unified entry (`http://localhost:80`)
  - `pnpm build` passing under TypeScript strict
- **Out of scope**:
  - Any concrete API client, endpoint, or mocked response
  - Selecting or wiring a mock tool (deferred to `debt.md`)
  - Login/auth UI, patient/booking/exam/report pages
  - A test runner (Vitest) - `verify.config.yaml` has `test: null` for this stack
  - DICOM viewer or image display components
  - `docker/` and any deployment configuration
  - CI workflow

## Design Constraints

- **Architecture constraints**: single SPA - departments are **lazy-loaded route modules**, not
  micro-frontends. Source organized as `src/{api,pages,components,stores,layouts,theme}` plus
  `src/router.tsx` (standalone route table) per the Module Layout requirement and
  `lumen-web/CLAUDE.md`. Function components and hooks only. Existing components are composed or
  extended, never modified.
- **Interface constraints**: `src/api/` exports `ApiEnvelope<T> { timestamp: string; code: string;
  msg: string; data: T | null }` - the OPS `R` contract the API spec was aligned to - and
  `BASE_PATH = '/api/v1'`, plus an `EntityId = string` alias (snowflake IDs
  are strings per `openspec/specs/api/spec.md` § ID Serialization). **No endpoint path is
  declared** - none exists in the API spec yet.
- **Dependency constraints**: pinned exactly (no `^`/`~`) per design D1, all verified against the
  npm registry on 2026-10-29 - `react`/`react-dom` 18.3.1, `antd` 5.29.3, `vite` 7.3.7,
  `@vitejs/plugin-react` 5.2.0, `typescript` 5.9.3, `react-router-dom` 7.18.5. The registry
  `latest` tags have moved past the project's constraints (React 19.x, AntD 6.x, Vite 8.x, TS 7.x)
  and MUST NOT be adopted here - plugin-react 6.x peers **only** Vite `^8`, which is why 5.2.0 is
  pinned alongside Vite 7. `pnpm-lock.yaml` is committed and is the reproducible artifact.
  `engines.node: "^20.19.0 || >=22.12.0"` (Vite 7's floor).
- **Data constraints**: no data fetching anywhere in this change. The placeholder routes render a
  static state and issue no request.
- **Theming constraint (binding)**: primary color MUST NOT be red - red is reserved for clinical
  alarm semantics (`lumen-web/CLAUDE.md`). Colors come from AntD theme tokens, never inline hex.
- **Verification constraint**: there is **no test runner**. L3 reports SKIP, so the only automated
  gate is the strict TypeScript build. Behavioral claims (lazy chunking, placeholder issues no
  request, primary is not red) are verified by inspection commands in `tasks.md` and at review.
  This weakness is recorded in `debt.md`.

## Test Obligations

- **Behaviors requiring failing-test-first**: **none** - this stack has no test runner
  (`verify.config.yaml`: `test: null`, L3 SKIP). TDD's red-green cycle cannot be applied here.
  Instead, every behavior is verified by the strict TypeScript build plus the inspection commands
  in `tasks.md`. Adding Vitest is a separate change and is logged in `debt.md`; when it lands, it
  must backfill failing-test-first coverage for all 13 approved behaviors and flip
  `verify.config.yaml` L3 from `null` to `pnpm test`.
- **Required edge cases** (verified by inspection, since none can be unit-tested yet):
  - **No invented endpoint**: `grep -rn "api/v1/" lumen-web/src` returns only `BASE_PATH`
    (scenarios 8, 10). This is the highest-value check in the change.
  - **Placeholder issues no request**: the radiology/ultrasound/endoscopy modules contain no
    fetch, axios, or API-client call (scenario 13).
  - **Primary color is not red**: the theme token definition has no red primary value
    (scenarios 11, 12).
  - **No hard-coded service host/port under `src/`** (scenarios 9, 10).
  - **Strict mode not weakened**: `tsconfig.json` shows `strict: true` and no broad `any` was
    introduced to silence the compiler (scenario 2).
  - **Lazy splitting actually happens**: the build output shows separate chunks for the department
    route modules (scenario 5) - otherwise they are not lazy and the micro-frontend-avoidance
    pattern is unproven.
- **Regression-sensitive areas**:
  - **The version pins.** Nothing enforces them after install except the committed lock file. A
    future `pnpm update` could pull React 19 / AntD 6 / Vite 8 / TS 7 and break the project's
    stated stack. Task 1.1's exact pins plus the lock file are the guard; review must reject a
    caret/tilde range on those six packages.
  - **TypeScript strictness.** With no test runner, `tsc` is the only automated gate - weakening
    it removes the stack's sole safety net.
  - **The proxy target.** It must stay in sync with the coordination doc's port table; if
    `init-backend-skeleton` changes the gateway port, this config silently points at the wrong
    place. Task 6.2 is the cross-check.
- **Characterization**: not applicable - greenfield, no existing un-specced code to baseline.
- **Known debt at time of writing** (`debt.md`): mock tool unselected (risk **med**, revisit when
  the API spec gains its first concrete endpoint); no test runner (risk **med**, revisit when
  Vitest is added); Vite pinned one major behind current (risk **low**, revisit in the stack
  upgrade proposal).

## Execution Mode

- **Mode**: `SDD`
- **Selection rationale**: 23 tracked tasks (>3), and although they are all inside the single
  `lumen-web` module, there is a material **risk indicator**: with `test: null` the L3 gate is
  SKIP, so **no automated check verifies behavior** - the strict build catches type errors only.
  Claims like "the placeholder issues no request", "the primary token is not red", and "the routes
  are genuinely lazy-split" have no test asserting them. SDD's independent reviewer dimension is
  therefore the only structured gate for those 13 behaviors, which is what the Batch Inline mode
  would omit. A secondary indicator is the version drift risk (registry `latest` is a major ahead
  of every pin).

## Review Gates

- **Mandatory review points**:
  1. **After Batch 1** (scaffold + pins) - blocking. Confirm exact versions, `strict: true`, the
     Node engine floor, and a committed lock file. Everything downstream inherits this.
  2. **After Batch 3** (API seam) - blocking. This is where an endpoint could be invented. Verify
     the grep shows only `BASE_PATH` and that `EntityId` is `string`.
  3. **After Batch 4** (proxy) - confirm the target port matches the coordination doc, since the
     sibling change writes to the same table.
  4. **After Batch 5** (shell/theming/routing) - blocking, and the most important review in this
     change: with L3 SKIP, this is the only place the 13 behaviors get human verification. Check
     the non-red primary, the absence of any request in placeholders, and the lazy chunk output.
- **Blocking categories**:
  - Any invented endpoint path in `src/` (violates scenario 8 and the Intent Lock).
  - Any data fetch in a placeholder route (violates scenario 13).
  - A red primary theme token, or inline hex replacing a token (violates scenarios 11, 12).
  - `strict: false`, a weakened tsconfig, or a broad `any` used to silence the compiler
    (violates scenario 2).
  - A caret/tilde range on the six pinned dependencies, or an uncommitted `pnpm-lock.yaml`
    (violates the dependency constraint).
  - React 19 / AntD 6 / Vite 8 / TypeScript 7 adopted (violates the project's stated stack; that
    is its own proposal).
  - A hard-coded service host or port under `src/` (violates scenarios 9, 10).
  - A micro-frontend or separately deployable department bundle (violates scenario 5).
  - A test runner added ad hoc, or `verify.config.yaml` edited to claim an L3 gate that does not
    exist - adding Vitest is a separate change that must also backfill the behaviors.

## Escalation Rules

- **When to rewind to proposing**: new scope appears; key design assumption wrong; interfaces
  change materially. Specifically for this change:
  - A concrete endpoint is needed to make the seam meaningful - the API spec has none, and
    inventing one is forbidden. That means a new proposal against `openspec/specs/api/spec.md`
    first, which will also trigger the deferred mock-tool decision (design D5).
  - The pinned Vite 7 + plugin-react 5.2.0 combination cannot build on the available Node runtime
    - the Node engine floor is a design constraint, and changing it is a proposal-level decision.
  - AntD 5 cannot satisfy the token-theming requirement, which would put the "AntD 5 first" coding
    standard in conflict with the spec.
  - The gateway port in the coordination doc changes, since the proxy target and the port table are
    a cross-stack contract.
  - Anyone asks for login UI, a real page, or a DICOM viewer - all outside the Intent Lock.
- **When NOT to continue**: contract intent lock no longer matches proposal scope. Concretely: do
  not proceed if the work has drifted into implementing behavior from
  `openspec/specs/{api,errors}`, wiring a mock tool, or adding a test runner - each is its own
  change. Do not "fix" a strict-mode error by relaxing the config; that removes this stack's only
  automated gate.
