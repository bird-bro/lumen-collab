## Coordinator-pinned binding decisions (apply, do not re-litigate)

1. **Service family** (naming.md business-service ruling): interface `PatientArchiveService` + `impl/PatientArchiveServiceImpl` — create / update / getById / page / resolve / resolveOrMerge. Interface `PatientEventOutboxService` + `impl/PatientEventOutboxServiceImpl` with ONE write method `void append(String eventType, Integer patientId, String payloadJson)` — append-only BY INTERFACE (no update/delete members). Pinyin helper is a stateless collaborator → `service/support/` per naming.md (e.g. `PatientPinyinHelper`), same-package `{@link}`s use the FQN.
2. **Create flow order** (single `@Transactional` service method): (a0) **id_type is REQUIRED whenever id_no is present** (A0410/A0400 — b1 review carry-forward: the identity index predicate does not pin id_type, so the service check is the only NULL-id_type guard); (a) in-service uniqueness check — id_no present on any LIVE archive (`deleted=0 AND merged_into IS NULL`, same id_type) → `BusinessException(ERROR_A0715, detail naming the duplicate: existing archive id + pat_id)`; (b) `patientNumberService.issue("pat_id")` — REQUIRES_NEW per b2 decision 1, so a failure after issuance burns the serial (task 2.3 semantics); (c) pinyin = helper on name (NULL name → NULL pinyin — unnamed emergency is legal); (d) insert master (archive_status per request flag; default RESOLVED); (e) insert identifier rows for the additional numbers the request carries (card/physical/outpatient/inpatient/his). All inside the caller's transaction except the issuance inner commit.
3. **Index backstop translation:** two concurrent creates with the same id_no both pass the in-service check → one hits the partial unique index → catch the Spring `DuplicateKeyException` on insert and re-throw as the SAME A0715 conflict payload (house pattern: in-service check = A-class path, index = backstop — V1__auth_schema header).
4. **Update flow:** demographics-only request DTO (NO archive_status field — the one-way PROVISIONAL→RESOLVED machine has no v1 endpoint; a DTO without the field cannot violate it). Re-run the id_no uniqueness check (excluding the row itself) on change; after a successful update write PATIENT_CHANGED (payload = the UPDATED archive serialized, hutool `JSONUtil.toJsonStr`) inside the same transaction. Updating a merged row → reject (merged rows are immutable history — B0003-family per house precedent; pick the exact house code by reading lumen-system's not-found/immutable precedents).
5. **Fetch / list:** getById returns the row REGARDLESS of merge state (spec: merged stays retrievable by id; merged_into present tells the caller). Default page list filters `deleted=0 AND merged_into IS NULL`; filters: name contains, pinyin prefix (LIKE 'x%'), pat_id exact, id_no exact, phone contains; MP `Page<T>` ordered id desc. Not-found semantics follow the lumen-system house precedent (verify from AuthOrgCrudTests / R.ofFail usage).
6. **Resolve chain** `resolve(request)`: request carries idType+idNo?, cardNo?, name?, gender?, birthDate?, phone?, provisional flag. Order: (i) exact `(id_type,id_no)` on a live archive → decisive MATCHED; (ii) exact card_no among live archives' identifier rows (id_type='card') → exactly ONE live hit = decisive MATCHED, 2+ hits = CANDIDATES (card_no is NOT unique — ambiguity demotes to candidates; document in javadoc); (iii) soft: union of (name+phone) and (name+gender+birth) exact matches on live archives, deduped by id → CANDIDATES (never an error — HTTP-200 envelope, task 3.3); (iv) nothing → CREATE (provisional flag → PROVISIONAL/RESOLVED) → CREATED. Response DTO: `{ result: MATCHED|CANDIDATES|CREATED, patient?: <archive>, candidates?: [<archives>] }` (naming yours, javadoc the contract).
7. **Resolve-or-merge** `resolveOrMerge(id, survivorId, reason?)`: body carries survivorId (the workstation caller resolves the survivor via the chain API first — the backfill flow lives in future workstation changes). Guards: self-merge (id==survivorId) → A0400; survivor must exist, be live, and be RESOLVED (merging into PROVISIONAL → A0400 detail); merged row must be live (already-merged → IDEMPOTENT: return the existing survivor, write NOTHING). Effect (one transaction): merged.merged_into = survivorId; survivor stays RESOLVED (no-op touch); merge_log row (mergedId, survivorId, reason, operator via MetaObjectConfig); PATIENT_MERGED outbox payload JSON naming BOTH ids explicitly: `{"survivorId":..,"mergedId":..}`. Return the survivor archive.
8. **Outbox:** PATIENT_CHANGED / PATIENT_MERGED event_type strings; rows are ONLY ever INSERTed (PENDING default); NO MQ/producer code, NO poller, NO status updates anywhere in the module. Task 3.5's test asserts: N appends → N rows all PENDING; and that the archive/merge flows succeed with no broker configured (the suite itself proves it — Redis/PG only).
9. **Pinyin dependency (the batch's additive dependency):** `io.github.biezhi:TinyPinyin:2.0.3.RELEASE` — EIS 1:1 coordinates (`lumen-reference/code/eis_scv-single-hospital/pom.xml:124`), used with Hutool `PinyinUtil.getPinyin(name)` exactly as EIS does (`OrderPatientServiceImpl:40`). Land the version ADDITIVELY in `lumen-bom` dependencyManagement (comment: EIS-lineage pin) + the patient pom dependency. Verify engine detection with the create test (Chinese name → non-null full pinyin); if Hutool cannot detect the biezhi engine on hutool 5.8.20, fall back to TinyPinyin's own API (`Pinyin.toPinyin`) inside the helper — record which landed. Polyphonic imperfection is accepted (design risk table: wrong pinyin only degrades search, never identity).
10. **Fixture discipline:** test-created archives consume REAL serials from the seeded `pat_id` rule (accepted residue — serials advance, gap-tolerant, no uniqueness impact after sweep). The suite captures every issued archive id in memory and `@AfterAll` hard-DELETEs master/identifier/outbox/merge_log rows by the captured id list (user ruling 2026-11-07: hard delete). Test archive names use a `b3检验` marker prefix as a secondary sweep key. Never touch b2's fixture families or the seeded rule row beyond consuming serials.
11. **Error codes:** A0715 id_no conflict (b2 additive constant); A0400 for malformed resolve/merge requests (self-merge, PROVISIONAL survivor, invalid stamp/format config surfaced through issuance); house B-codes for not-found/immutable rows. No new enum constants without coordinator approval — if you need one, propose it in the report.
