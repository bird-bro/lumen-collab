# 机构与科室管理重构说明（非权威概览）

> 本文件是面向业务与实施讨论的中文说明；`openspec/` 下的英文提案与规格才是权威来源。

## 背景与结论

当前“机构管理”是一个通用的多根组织树，只有名称，能随意新建根机构；科室可以挂到任意机构节点。这个模型适合早期脚手架，但不能稳定表达院内版本最常见的场景：**一家医院、多个院区/分院**。同时，大型医院的科室数量较多，如果继续用一棵混合“院区 + 科室”的大树维护，检索、筛选和分页都会变得困难。

本次确认方向如下：

- 院内版本第一版按 **单医院、多院区** 设计。
- 机构管理页面改为“左侧医院信息卡片 + 右侧院区列表”。
- 原来的“医院/院区树”移动到科室管理页面，只作为科室检索过滤条件。
- 科室仍然是独立资源，不放进机构树；科室必须归属到院区。
- 同名/同编码科室可以在不同院区存在，例如“总院区放射科”和“东院区放射科”。
- 普通管理员不应随意新建根机构。
- 集团多医院、外部合作机构、用户院区数据权限、PACS/HL7 接入配置属于后续变更，不在本次范围内。

目标结构：

```text
医院
├── 总院区
│   ├── 放射科
│   ├── 超声科
│   └── 内镜中心
├── 东院区
│   ├── 放射科
│   └── 超声科
└── 浦东分院
    ├── 放射科
    └── 内镜中心
```

## 页面交互设计

### 机构管理

```text
机构管理
┌──────────────┬────────────────────────────────────────────┐
│ 医院信息卡片  │ 院区列表                                    │
│              │ [搜索] [状态] [新增院区]                     │
│ 名称：...     │ ┌────────────────────────────────────────┐ │
│ 代码：...     │ │ 院区 | 代码 | 默认 | 状态 | 操作         │ │
│ 状态：...     │ │ ...  | ...  | ...  | ...  | 编辑/删除  │ │
│ 地址：...     │ └────────────────────────────────────────┘ │
│ [编辑医院]    │                                            │
└──────────────┴────────────────────────────────────────────┘
```

- 左侧不再放“医院/院区树”，只展示医院关键资料和编辑入口。
- 右侧用表格维护院区，支持关键字/状态过滤、新增、编辑、设为默认院区、删除。
- 页面不提供普通“新建根机构”入口。
- 页面可以提供跳转到科室管理的上下文入口，但科室维护不放在这里。

### 科室管理

```text
科室管理
┌──────────────┬────────────────────────────────────────────┐
│ 医院/院区树   │ 科室列表                                    │
│ ● 全部院区    │ [关键字] [状态] [新增科室]                   │
│ ├ 总院区      │ ┌────────────────────────────────────────┐ │
│ ├ 东院区      │ │ 院区 | 科室 | 代码 | 状态 | 操作         │ │
│ └ 浦东分院    │ │ ...  | ...  | ...  | ...  | 编辑/删除  │ │
│              │ └────────────────────────────────────────┘ │
└──────────────┴────────────────────────────────────────────┘
```

- 左侧树只包含医院和院区，不包含科室；它只负责定位。
- 选中医院根节点表示“全部院区”；选中某个院区则过滤该院区科室。
- 右侧科室表格使用服务端分页，并支持关键字、状态、院区过滤。
- 新增/编辑科室时必须选择一个启用中的院区。
- 选中院区时，表单预填该院区；选中“全部院区”时，表单要求显式选择院区。
- 编辑时科室代码不可修改；跨院区查询结果中要显示院区，避免同编码科室混淆。

## 初始化说明（方案 B）

新部署不需要在安装参数里填写医院资料。系统初始化时默认生成：

- 一个可编辑的医院根节点：`未命名医院`
- 一个默认院区：`总院区`
- 对应的受控初始代码，保证必填和唯一性约束可满足

管理员首次进入系统后，在“机构管理 → 医院信息卡片”里点击“编辑医院”，补齐医院名称、代码、省市区、地址、联系人等信息。页面在初始化占位状态下展示“待完善”提示；这个流程只调用普通的机构编辑接口，不提供“新建根机构”入口。

已有环境迁移时，已有医院名称保持不变，只补默认院区并把原直属科室迁移过去。原始示例种子机构会归一化为上述初始化占位状态。

## 后端模型要点

- `org_info.type = 0` 表示医院，`type = 1` 表示院区。
- 线上运行时最多存在一个医院根节点。
- 医院下可以创建院区；院区不能继续创建子机构。
- 机构类型创建后不可修改；第一版不允许重新挂父级。
- 有子机构或科室的机构不能删除。
- 机构扩展代码、简称、状态、省市区、地址、联系人、电话、邮箱、Logo URL、排序、默认院区等字段。
- 科室的 `org_id` 必须指向启用中的院区；医院根节点不能作为科室归属。
- 科室增加状态字段，便于列表过滤和启停展示。
- 科室代码创建后不可修改；在同一个院区内唯一，不同院区可以使用相同代码。
- 保留现有科室列表接口，并新增科室分页查询接口，支持关键字、状态、院区过滤。
- 迁移时保留现有科室 ID 和代码，先为医院创建默认院区，再把原直属科室迁移过去，并默认置为启用。

## 前端行为要点

- 机构管理不使用通用机构树；左侧是医院资料卡片，右侧是院区表格。
- 隐藏普通“新建根机构”入口。
- 初始化采用方案 B：系统先提供可编辑的“未命名医院/总院区”，管理员通过普通编辑表单补齐资料。
- 只有医院维度提供“新增院区”。
- 编辑机构时不再暴露类型和父级修改。
- 新建院区必填机构代码。
- 删除机构前确认；后端因存在子机构/科室拒绝时，直接显示后端消息。
- 科室页面的树只用于过滤；医院节点表示“全部院区”，不是科室归属。
- 科室新增/编辑统一使用右侧表格触发的表单，并显式选择院区。
- 保持现有权限门控：机构用 `system:org:list`，科室用 `system:dep:list`。
