叁 · 紧凑化对照v1（RCP 列表+抽屉）→ v2（EIS 工作台）
① 结构：整页列表 + 560px 抽屉点开才见表单 → 常驻工作台：左 rail 今日登记单 + 右表单。EIS register/check 同构；少一次开抽屉，列表与表单同屏互证。
② 表单密度：竖排 label、12 字段两列、大间距 → label 左置 72px、三列网格、行距 9px、输入高 28（EIS label-width 100 的密度）。 解析条从 v1 的三列查询带压成单行（键型 Segmented + 输入 + 查询，EIS 顶部登记号查询行同位）。
③ 分段：①患者信息 ②孕检信息 ③检查信息 三段 → 两段合并：孕检字段并入 2、请检信息（妊娠状态/孕周本来就是请检属性）； 急诊开关嵌进节标题行（EIS 急诊开关在标题行的同款手法，也满足 2026-11-19 开关行房规）； 占位不再单独设开关——急诊单姓名可留空，留空即无名氏占位档（决策#3 语义不变；实现上服务端本就按 name=null 判占位，去掉显式占位字段后契约零变更）。
④ 列表压缩：九列表格 → rail 三列（患者/项目三行复合 + 状态 + 行操作）， 检查号/时间并入患者格第三行；状态筛选改 chips 带计数（EIS ReportStatusCheckbox 同款—— 多选切换，默认 预约+已登记=今日在册；不放 RCP 式下拉：计数是登记台的工作量仪表，下拉会藏掉它， 且窄面板无查询行、状态筛选只能住头部）。 取消原因 tooltip、状态色板、占位虚框 tag 照搬 v1。
⑤ 动作落位：抽屉 footer「保存」 → 工作台右下「重置 + 提交登记」（EIS 同位同名）； 行操作仍只有 登记 ✓ / 取消（v1 无编辑/打印/影像后端，不预画）。
⑨ 预登记并入工作台：所谓预约即预登记（用户 2026-11-23 定义，如产检预登记到某天某时段）—— 预登记 = 日期 + 时间段两个值（默认 今天·即到即检，选未来时段即为预登记单）， 落点内核 exam_order 新增 booking_time（现表只有 booking_no 预约号列，无预约时间—— Vendored DDL 下一次 V 号补）。 rail 加日期切换（‹ 今天 ›），未来时段的单落 BOOKED（预登记态）、到日出现在当日列表；取消预登记复用 取消。 EIS 的 登记/预约双页不跟——rail 日期 nav 已是预登记管理雏形；号池时段容量格（预留/满约/冲突）不进 v1，容量只做静态每档上限（拍板 06）。
⑩ rail 两态（紧凑登记态 / 宽表查询态）：宽表是需求本体（护士要看更多列 + 更多查询条件）， 曾被误当手段修剪，恢复；「完全收缩」则确无意义而退役（表单不需全宽，收列表伤互证）。 紧凑态 = 登记主场（chips + 日期 nav + 复合行，不铺查询行——整行条件条浪费列表纵向空间，用户 2026-11-23 点名）；宽表态 = 查询主场： rail 接管全宽，查询条件行（我的查询 + 申请时间/姓名/检查号 + 更多条件 + 查询/重置）+ 全列（患者复合/检查项目/状态/急诊/孕检/检查号/创建时间/临床诊断/操作）， 行操作照旧（登记/取消），同一组件宽度态切换非第二页面。切换 affordance 一枚：面板右缘中线圆钮 »/«。 宽表查询条件 = RCP ∪ EIS 综合，两层结构（两家同款）：常驻行 申请时间范围（默认今天）/ 患者姓名 / 检查号 + 更多条件展开行 患者编号 / 患者类型 / 检查项目（模糊）/ 就诊卡号（EIS 登记号的对应物）。 不搬：院区/检查机构/检查室（多机构与房间绑定 v1 无）、登记医生/诊断医生/请检医生/请检科室（HIS 单 v1 无）、检查部位（项目内含）、检查类型（US 固定免筛）。 患者编号/患者类型/检查项目/就诊卡号/时间范围 需后端查询扩展（拍板 03 一并落）。 头部随面板分层：窄态 rail-head = datenav 按天翻看（唯一时间入口）+ chips + 刷新； 宽态 rail-head = chips + 刷新，datenav 隐去——时间条件由 xhead 申请时间范围接管，避免双时间入口； 两处共享同一日期状态（窄态翻到的日子 = 宽态 range 的默认值）。 另保留 RCP 两件：我的查询（行尾动作簇：查询/重置之后——填完条件、保存当前条件、点选即查一个位置闭环， 字段行保持纯字段；后端持久见拍板 07） 与列设置（表头操作列滑杆图标，列显隐/排序 localStorage 记忆，EIS useHeaderColumn 同款）。
范围外不搬：EIS 的 号池时段容量格（BookingNumber 的 预留/已约/可约/满约 容量管理——lumen v1 只做静态每档上限校验， 号格实体/预留/锁定等真预约体系见拍板点 06）、条码打印开关（本地打印驱动）、HIS 开单查询（请检科室/请检医生/申请单号字段——v1 无 HIS 单）。 RCP 的 1200px 抽屉形态随 v1 一起退役。
⑥ 小屏保障：不再设「完全收缩」形态——表单三列在 ~900px 即舒展，收起列表反而失去登记时同屏看单的互证； <1180px 极窄屏由响应式上下堆叠兜底（列表在上）； 实现直接用壳层现成的 ConsoleWorkArea（360px aside + 主面板，机构/科室页同款两区布局），不新造布局； 表单三列在内容区变窄时降两列、极窄时上下堆叠（列表在上）。1366×768 笔记本实测是验收门槛之一。
⑦ 年龄三输入（岁/月/天 三个文本框）：值带单位尾标、空格占位即单位，成人只填岁格，儿童填岁+月，新生儿填天格（0岁0月5天）。 三格在前端组编为契约 age 单字符串：空/零单位自动裁剪——34岁 / 2月5天 / 5天； 0 是合法值（新生儿岁=月=0），列表患者格回显同串。三格是录入 UI，契约不做结构变更。
⑧ 妊娠格：条件显示 + 一格录完：性别非女时整格隐藏（不渲染、不提交——实现用 Form.useWatch('gender') 条件渲染，demo 里点患者信息的 性别 男/女 可试）； 女时一格录完——妊娠状态下拉 + 孕周数字（未孕/未知免填孕周，孕周格禁用）。 合并是 UI 编组，契约仍是 ext.pregnancyStatus + ext.gestationalWeeks 两字段。

DECISION 01

页面形态：单页工作台 vs 双页拆分

A 单页工作台（左今日单 rail + 右登记表单）B EIS 式双页（登记工作台 / 登记管理两个菜单）

A 一个菜单节点装下「看单 + 登记」，菜单种子不动；B 是 EIS 的原始拆法（register/check + register/manage）， 要加菜单节点、拆两个 spec 场景，v1 登记单量下收益有限。

建议：A（B 在登记量上来后随时可拆，列表 rail 已是管理面的雏形）
DECISION 02

提交语义：提交即登记（1 步）

A 保持两步B 提交即登记（用户裁决 2026-11-23，EIS/RCP 同款）

B 定案。状态语义随「预约=预登记」重定义：现场单（即到即检）提交 → 单事务内 create+register， 直接落 已登记（RCP/EIS 的 commitOrder 同款一呼叫）；预登记单（选未来时段，如产检预登记到某天某时段） → 落 BOOKED（预登记态），患者到检后在列表点 登记 完成到检确认。BOOKED 的含义从「预约」改为「预登记」。 后端实现建议 create 单事务按 booking_time 推导状态（now=即到即检 → 已登记；未来 → 预登记）， 显式 registerFlag 参数作为备选，随提案定。

已定：B（内核 BOOKED→REGISTERED 状态机不变，只是入口语义升级；「登记」仍是预登记单的到检确认动作）
DECISION 03

宽表查询条件与状态计数

B RCP∪EIS 综合条件集 + 状态计数 chips（后端一个提案）A 现有查询三键，无计数

常驻行：申请时间范围（默认今天）/ 患者姓名 / 检查号；更多条件展开行：患者编号 / 患者类型 / 检查项目（模糊）/ 就诊卡号。 现有查询只有 状态/检查号/患者姓名——其余键是 jsonb 快照 where + 时间范围/状态多选 + 状态计数端点， 全部落进一个后端轻量提案（mapper 一处 where 级别）。紧凑态不设查询行，查数一律进宽表态（RCP 同构）。

建议：B（登记台以「今天」为工作面，宽表是查数主场，条件一次配齐）

检查项目选择器

A 常用项目 chips + 已选列表（含单价合计）+ 添加弹窗B 保持 Select 多选

建议：A（v1 目录无组套概念，chips 够用；组套来了再演进）
DECISION 05

临床信息字段边界

A 妊娠状态/孕周/临床诊断（临床诊断由 ext.note 承载，契约零变更）B ext 再扩主诉/病史摘要

DECISION 06

预登记承载形态 + 时段容量

A 单页内预登记（booking_time + rail 日期切换）B EIS 双页：登记台/预约台分菜单C v1 不做预登记

B 随拍板 01 失去必要性；C 让现场失去「产检预登记到明天/下午」的能力。时段容量（已定：最小静态容量，内核级通用）： 时段粒度（默认 30 分钟）、每时段上限（默认 4 人）、开台时间窗（如 08:00–12:00 / 14:00–17:00）—— 配置实体与容量校验服务放 lumen-core（科室中立，radiology/endo 建工作站时 vendor 复用，用户 2026-11-23 指认其他科室也需要）， 预登记提交按 booking_time 档位 count 校验，满员时段下拉标灰禁选（"08:00–08:30 已满 4/4"）+ 提交拦截双保险。 不做号格实体/预留/锁定/跨日排班——EIS 号池（BookingNumber）的 v2 提案范畴。

已定：A + 最小静态容量；容量机制随 booking_time 独立成内核预登记提案（科室中立），US/前端提案消费之
DECISION 07
